This document defines the first bootstrap layer required for a regular AI to receive the current
EPRA files, load them in the correct hierarchy, instantiate EP in a controlled way, reject drift,
and produce repeatable EP behavior. It is not a replacement for the mother-body or the
energetic methodology substrate. It is the activation bridge between them.
1. Purpose
The purpose of the bootstrap layer is operational. The current formal corpus already contains two
strong components:
• the mother-body architectural layer, which defines identity, ontology, relational grammar, axioms,
dynamics, operators, projection rules, reconstruction protocol, validity tests, and theorem
roadmap;
• the energetic methodology substrate, which defines the primitive energetic grammar, graph/state
representation, operator family, canonical pipeline, and objective structure.
What remains underdetermined is theingestion path. A regular AI may receive the files and still
fail to activate EP correctly if the file hierarchy, load order, setup order, and failure gates are not
stated in a compact operational form.
The bootstrap specification solves that problem.
2. Bootstrap objective
The bootstrap layer must satisfy five conditions simultaneously:
Loadability : a regular AI can infer file roles deterministically, (1)
Order discipline: setup proceeds in the right sequence, (2)
Membership integrity: pseudo-EP and drifted EP are rejected, (3)
Repeatability : similar tasks produce structurally similar setups, (4)
Projection control: derived outputs do not replace the mother-body. (5)
A bootstrap layer that fails on any one of these conditions is inadequate.

5. Canonical setup procedure
5.1. Setup objective
The bootstrap layer must force setup rather than paraphrase. The central procedure is
SetupEP(FCS, Methodology, Task) .
Its output is not a plain-text answer. Its output is anactive EP configurationfor the task.
5.2. Setup stages
The required setup sequence is:
1. System identification: determine the systemS under analysis.
2. Energetic-form identification: determine the active energetic form setKact.
3. Primitive instantiation: instantiate source, sink, gradient, path, barrier, loss, and when
relevant storage and conversion.
4. Structural mapping: instantiate maintenance, control, reproduction, externalization, legiti-
macy, information integrity, deviation, and fragility.
5. State construction: build the working state variables for the task.
6. Operator selection: choose the admissible operator path required for the task.
7. Validity gating: test whether the setup is actually EP.
8. Output production: emit an EP answer only if the required gates pass.

7. Validity gates
7.1. Gate structure
The bootstrap layer must operationalize the mother-body validity tests into a practical gating
sequence. The minimum gate set is:
1. Identity gate: has the hierarchy been loaded correctly?
2. Ontology gate: are the correct object sets being used?
3. Relational gate: are the mappings well-formed under the relational grammar?
4. Axiom gate: does the setup violate any core axiom?
5. Dynamics gate: if dynamic claims are made, are they linked to state/update logic?

8. Failure classifications
8.1. Pseudo-EP
A pseudo-EP output uses EP-like language but fails the structural gates. It may mention energy,
flow, control, or fragility, yet not instantiate the mother-body correctly.
8.2. Weak EP
A weak EP output captures part of the structure correctly but does not carry the full activation
path. This may be acceptable for partial notes or early drafts, but it is not sufficient for bootstrap
certification.
8.3. Drifted EP
A drifted EP output preserves some style and some terms while mutating the actual ontology,
relations, or axioms. This is more dangerous than plain non-EP because it can pass superficial

8.4. Non-EP

9. Projection discipline
The bootstrap layer must protect the priority rule that papers and other outputs are projections,
not ontology.
Any generated note, paper, case, memo, or summary must therefore carry projection metadata
stating:
• what mother-body slice it projects,
• what invariants it covers,
• what it omits,
• how it contributes to reconstruction,
• whether it is authoritative, illustrative, or merely communicative.
This is essential because a regular AI will otherwise tend to flatten the distinction between constitu-
tional layer and surface output.

11. Gold and anti-gold examples
11.1. Gold examples
The bootstrap pack should include a small set of canonical successful setups. Each example should
minimally contain:
• input task,
• identified system,
• active energetic forms,
• primitive instantiation,
• structural mapping,
• operator selection,
• validity result,
• final EP output.
11.2. Anti-gold examples
The bootstrap pack should also include failed setups showing:
• pseudo-EP,
• weak EP,
• drifted EP,
• energetic vocabulary with invalid structure,
• projection outputs that improperly claim ontological status.
This is the fastest way to teach a regular AI what to reject.

13. Completion criterion
The bootstrap phase should be considered minimally successful only if a regular AI, given the files
and no extra hidden instruction, can:
1. load the files in the correct hierarchy,
2. identify the mother-body as ontologically primary,
3. instantiate EP on a new task through the canonical setup procedure,
4. reject pseudo-EP, weak EP, and drifted EP when required,
5. produce an EP output with repeatable structural integrity.
That is the true criterion of bootstrap completion.
14. Closing statement
The bootstrap layer is the first operational bridge from formal completion to reproducible activation.
The theorem program gives EPRA its formal backbone. The bootstrap pack gives that backbone
a reliable ingestion path. Once the bootstrap layer exists, the system will no longer depend on
informal reading discipline alone. It will have a defined path by which a regular AI can receive the
corpus, activate EP correctly, and remain inside the paradigm’s own structural constraints.
